# E8—E10 B4 个人实验设计

## 意图

在 `student/241880300/e8-e10` 上按 B 组手册连续完成 E8、E9、E10，并留下可追溯的个人报告、运行证据和一个独立贡献。B4 贡献聚焦候选验证失败时的拒绝与源 `Makefile` 字节保护。

## 目标

- 将分发包中规定的实验运行入口、实验代码和 Actions workflow 导入外层课程仓库根目录。
- 运行 B 轨道 E8/E9/E10，保存每次 OUT、步骤日志、JSON、Patch、sandbox 和阶段结论。
- 新增一个独立预期的测试：编译失败的候选必须被拒绝，且源 `Makefile` 保持原字节。
- 填写个人报告、ADR 和 AI 使用记录，区分外层学生源码提交与实验样例内部提交。

## 非目标

- 不做 E11—E12 跨组产物交换和联调。
- 不替组长合并本分支到组 `main`，不代替本人完成 GitHub PR 审核。
- 不实现论文级完整 Make/编译器分析器；沿用教学包的受限输入模型。

## 约束

- 个人分支必须是 `student/241880300/e8-e10`。
- 当前主机没有 Docker Desktop 和 `gh`，因此本地运行使用 WSL2 Ubuntu 的 gcc、GNU Make、strace；仓库 workflow 仍使用手册要求的 Docker 环境。
- `work/` 作为本地/归档证据目录保持被忽略，不把临时凭据、`.env` 或缓存提交进 Git。

## 方案

1. **根目录导入运行包（采用）**：复制 `03_实验包` 中的 `run_lab.py`、`labs/e8e10` 和 workflow 到仓库根目录，最贴合手册和 CI 路径。
2. **整包嵌套导入**：把整个 `DevOps_E8_E10` 目录提交进仓库；材料完整但会使手册中的根目录命令失效，并混入授课资料。
3. **只提交报告**：不提交实验入口和独立测试；无法证明个人贡献，也不能让组长在 main 上复现。

方案 1 的代价是本地 Windows 不能直接执行 Docker 镜像构建；用 WSL2 验证核心实验，并保留 CI 作为标准 Docker 门禁，能覆盖这个限制。

## 实现边界

- `run_lab.py`：保留课程入口和镜像/输出目录约束。
- `labs/e8e10/lab.py`：使用分发包实现，不扩大教学范围。
- `labs/e8e10/test_profile.py`：增加 `StudentE10B.test_build_failure_keeps_original_makefile`。
- `docs/students/241880300/e8-e10/`：个人报告、ADR、AI 使用记录和证据索引。
- `work/`：保存 E8、E9、E10 B 的真实运行产物。
